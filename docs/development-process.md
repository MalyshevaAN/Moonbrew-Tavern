# Процесс разработки

## Подход к разработке

Проект лучше делать небольшими законченными этапами. Каждый этап должен добавлять видимую часть игры, а не только внутреннюю систему.

Предлагаемый порядок:

1. Сцена таверны.
2. Один посетитель.
3. Диалог с выбором ответа.
4. Приготовление одного напитка.
5. Реакция посетителя.
6. Награда.
7. Улучшение таверны.
8. Сохранение прогресса.
9. Расширение контента.

## Организация работы

Для разработки можно использовать простую схему:

- `main` — стабильная версия проекта;
- отдельные ветки для новых частей;
- короткие понятные коммиты;
- документация обновляется вместе с изменениями проекта.


## Проверка результата

На каждом этапе нужно проверять:

- запускается ли проект;
- понятен ли игровой экран;
- работает ли основной сценарий;
- не ломается ли сохранение;
- удобно ли играть на мобильном экране.

## Основные этапы

1. Проектирование.
2. Создание Android-проекта.
3. Базовая сцена таверны.
4. Основной игровой цикл.
5. Прогрессия и сохранение.
6. Расширение контента.
7. Полировка визуала и интерфейса.
